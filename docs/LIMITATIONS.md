# Ограничения

## Требования к телефону

- Android 8.0+ (API 26), только **arm64-v8a**.
- ОЗУ: ASR и диаризация — ~0,5 ГБ. Итоги (LLM) — свой пик ~2,0–2,1 ГБ (+ ~1 ГБ весов, читаемых
  с диска; их система может вытеснить). Перед LLM проверяется свободная память: если её мало,
  итоги не строятся (причина — во вкладке «Итоги»), расшифровка сохраняется. Ориентир для итогов —
  телефон с 6 ГБ ОЗУ и больше.
- Свободное место: APK 1,3 ГБ + копия моделей ~1,2 ГБ + кэш весов LLM ~1 ГБ (создаётся при первых итогах).

## Длина записи

- Аудио декодируется в память целиком (16 кГц float = ~3,8 МБ на минуту): час записи ≈ 230 МБ.
  `largeHeap` поднимает лимит памяти приложения (эмулятор: 192 → 576 МБ). Первый проход диаризации на записи
  длиннее 10 мин идёт окнами по 10 мин (перекрытие 30 с): sherpa держит буферы только на окно.
- Если рядом с записью не помещается даже копия одного окна (на телефоне с 512 МБ — запись примерно от 1,5 ч),
  диаризация пропускается: вся речь — один спикер, расшифровка не падает. Записи длиннее 10 мин на телефоне
  пока не проверялись.
- Foreground Service типа `mediaProcessing`/`dataSync` на Android 15+ ограничен 6 часами в сутки.

## Известные проблемы и упрощения каркаса

- Итоги строятся по первым ~8500 символам расшифровки (≈ 10–15 мин разговора): больше не влезает
  в контекст модели на телефоне. Итоги длинной записи помечаются «по первым N мин записи».
- LLM на CPU телефона медленная (эмулятор: 3–7 мин), поэтому идёт уже после показа расшифровки и в RTF
  не входит. Новая обработка прерывает анализ предыдущей записи — у неё не будет итогов.
- Итоги от модели 1,7B на играх и бессвязной болтовне бывают с выдумками и повторами; в деловых разговорах
  изредка путаются суммы. Участников в итогах модель не называет (кроме поручений): иначе она приписывала
  ведущему рассказ гостя.
  Роли участников модель путает, поэтому имена берутся только из самопредставлений («Я Лёша»,
  «в гостях у нас Нюта» в разговоре двоих); иначе — «Спикер N».
- LLM-правка не попадает в строгий экспорт, пока не доказана польза для WER.
- Плеер WebView не играет amr/3gp/wma — для них при импорте делается WAV-копия (удваивает место).
- Одна обработка за раз.
- «Отмена» во время диаризации срабатывает только после окончания этапа: sherpa-onnx не умеет прерывать
  его посередине. Интерфейс об этом предупреждает.
- Скорость на эмуляторе (1 ядро) не показательна: диаризация там в ~17 раз медленнее, чем на ПК в один поток.
