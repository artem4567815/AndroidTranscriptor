# Ограничения

## Требования к телефону

- Android 8.0+ (API 26), только **arm64-v8a**.
- ОЗУ: ASR и диаризация — ~0,5 ГБ. Протокол (LLM) — свой пик ~2,0–2,1 ГБ (+ ~1 ГБ весов, читаемых
  с диска; их система может вытеснить). Перед LLM проверяется свободная память: если её мало,
  протокол не строится (причина — во вкладке «Протокол»), расшифровка сохраняется. Ориентир для протокола —
  телефон с 6 ГБ ОЗУ и больше.
- Свободное место: APK 1,3 ГБ + копия моделей ~1,2 ГБ + кэш весов LLM ~1 ГБ (создаётся при первом протоколе).

## Длина записи

- Аудио декодируется в память целиком (16 кГц float = ~3,8 МБ на минуту): час записи ≈ 230 МБ.
  TODO(роль 3): потоковая обработка для записей длиннее ~1,5 ч.
- Foreground Service типа `mediaProcessing`/`dataSync` на Android 15+ ограничен 6 часами в сутки.

## Известные проблемы и упрощения каркаса

- Протокол строится по первым ~9000 символам расшифровки (≈ 10–15 мин разговора): больше не влезает
  в контекст модели на телефоне. Протокол длинной записи помечается «составлен по первым N мин».
- LLM на CPU телефона медленная: этап «Протокол» на эмуляторе ~3,4 мин на 3 мин записи
  (см. docs/TESTS.md). Выключается переключателем на экране «Обработка».
- LLM-правка не попадает в строгий экспорт, пока не доказана польза для WER.
- Плеер WebView не играет amr/3gp/wma — для них при импорте делается WAV-копия (удваивает место).
- Одна обработка за раз.
- «Отмена» во время диаризации срабатывает только после окончания этапа: sherpa-onnx не умеет прерывать
  его посередине. Интерфейс об этом предупреждает.
- Скорость на эмуляторе (1 ядро) не показательна: диаризация там в ~17 раз медленнее, чем на ПК в один поток.
